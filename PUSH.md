# Getting this onto GitHub

The repo is already initialised with three commits and a clean tree. You only
need to authenticate and push — which is the part you should do yourself, since
it's the only step that touches your credentials.

## Option 1 — `gh` CLI (easiest)

```bash
gh auth login                    # browser flow, no token pasting
cd umapilot
gh repo create umapilot --public --source=. --remote=origin --push
```

That creates the repo and pushes `main` in one command.

## Option 2 — create the repo in the browser

Make an empty repo (no README, no .gitignore, no licence — this repo has them),
then:

```bash
cd umapilot
git remote add origin git@github.com:<you>/umapilot.git
git push -u origin main
```

SSH is worth the two minutes over HTTPS: no token to store or rotate.
`gh auth login` sets it up for you, or `ssh-keygen -t ed25519` then paste the
`.pub` into GitHub → Settings → SSH keys.

## Before you push

The tree is clean and no game data is tracked, but it costs nothing to confirm:

```bash
git ls-files | grep -E '\.mdb|generated/.*\.json'    # must print nothing
```

`.gitignore` excludes `*.mdb` and `packages/data/generated/*.json`. The extractor
is the artifact; the data is regenerated by each user from their own install.

## Authorship

Commits use a GitHub `users.noreply.github.com` address, so your real email
never appears in public commit metadata. Commits still link to your profile and
count toward your contribution graph.

Your noreply address is shown at **GitHub → Settings → Emails**, in the form
`<id>+<username>@users.noreply.github.com`.

While you are on that page, tick **"Keep my email addresses private"** and
**"Block command line pushes that expose my email"**. The second one is the
useful safety net: it rejects any future push that would leak your real address,
rather than relying on you remembering to configure each clone.

To point a clone at the right identity:

```bash
git config user.email "<id>+<username>@users.noreply.github.com"
```

## CI

`.github/workflows/ci.yml` runs on push and PR: typecheck, extractor self-checks,
JSON Schema validation, and the smoke suite. All four pass without any game data
present — the smoke job skips itself when there's no dataset, which is always the
case on a runner. Nothing to configure, no secrets needed.
